From Tidy to Wide without Aggregation

DS 2023 | Communicating with Data

Overview¶

A previous notebook, Two Ways from Tidy to Wide, describes how to create wide tables from tidy tables.

That notebook assumed the following:

  • You have a tidy DataFrame DDD with two grouping variables g1g_1g1​ and g2g_2g2​ and one measurement variable mmm.

  • You want a wide table WWW with g1g_1g1​ on axis 0, g2g_2g2​ on axis 1, and mmm in the cells.

The notebook shows two ways to create WWW, depending on the question:

  • Do g1g_1g1​ and g2g_2g2​ combine to produce a unique set over the observations?

  • If yes, reshape. If no, aggregate and reshape.

This notebook takes up the case where aggregating is not acceptable.

That case arises constantly once we start plotting distributions.

For example, a histogram, a density plot, and a box plot each require every observation.

Replacing a group with its mean destroys the very thing we are trying to draw.

Its condition is therefore the following:

  • You have a tidy DataFrame DDD with one or more grouping variables, which we refer to collectively as ggg, and one measurement variable mmm.

  • The values of ggg do not form a unique key over DDD. Some combination of them occurs more than once.

  • Aggregating is not acceptable, because you need every observation.

  • You want a wide table WWW with the levels of ggg on axis 1 and every value of mmm running down the columns.

Important

Note what does not matter here: how many grouping variables you have.

What matters is that they fail to identify a row.

A single variable may fail, as species does in iris below, and so may a combination, as species and sex do in penguins.

The solution is to manufacture one more grouping variable, chosen so that it completes the key. We will call it www, a within-group ID.

The solution is to manufacture the one you are missing. We will call it www, a within-group ID.

This will the ID of the observation that will be unique within each group.

When we reshape, www plays the role of g1g_1g1​ and lands on axis 0, and ggg plays the role of g2g_2g2​ and lands on axis 1.

Example 1¶

We use iris, which records four measurements for 150 flowers of three species.

Get the data¶

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns

iris = sns.load_dataset('iris')
iris.head()

Choose the variables¶

Note that we have only one grouping variable. We assign ggg and mmm.

a_g = 'species'
a_m = 'petal_length'

Check for uniqueness¶

With only one grouping variable, the question is whether ggg alone identifies a row.

Value counts returns results in descending order, so any values greater than 1 would appear first.

iris.value_counts([a_g]).head(1)
species setosa 50 Name: count, dtype: int64

We see that species is not unique.

There are 50 flowers of each species.

By the previous notebook we would now aggregate.

But we want a box plot, so we need all 150 measurements. We continue down the new branch.

See what goes wrong without an index¶

It is worth seeing what Pandas does if we ask for the reshape and give it no index.

staircase = iris.pivot(columns=a_g, values=a_m)

print('shape:      ', staircase.shape)
print('total cells:', staircase.size)
print('cells filled:', staircase.notna().sum().sum())

staircase.iloc[48:53]
shape:       (150, 3)
total cells: 450
cells filled: 150
Loading...

So, no error was raised — but the table is useless.

Lacking an index, Pandas used the dataframe’s original row numbers. Every original row number belongs to exactly one species, so each row holds one value and two blanks. The result is 150 values scattered across 450 cells in a staircase.

What we need is a row label meaning the nth flower of its species, so that the first setosa, the first versicolor, and the first virginica all land on row 0.

Manufacture www¶

The method is .cumcount(). Applied to a groupby object, it numbers the rows within each group, starting at 0 and starting over at each new group.

a_w = 'within'

iris[a_w] = iris.groupby(a_g).cumcount()

The behavior to notice is what happens at a group boundary. iris is ordered by species, so the change occurs at row 50.

iris.loc[48:52, [a_g, a_m, a_w]]
Loading...

The counter reaches 49 at the last setosa and resets to 0 at the first versicolor.

Each species is therefore numbered 0 through 49, and w×gw \times gw×g is now unique. We can verify this with the same check we used above.

iris.value_counts([a_w, a_g]).head(1)
within species 0 setosa 1 Name: count, dtype: int64

Reshape¶

Having manufactured www, both methods from the previous notebook apply unchanged, with www in the g1g_1g1​ position and ggg in the g2g_2g2​ position.

Method 1: Pivoting¶

iris.pivot(index=a_w, columns=a_g, values=a_m).head()
Loading...

Method 2: Unstacking¶

iris.set_index([a_w, a_g])[a_m].unstack().head()
Loading...

The staircase has collapsed from 150 rows into 50, with every cell filled.

WWW is now in the shape our plotting functions expect.

iris.pivot(index=a_w, columns=a_g, values=a_m).plot.box(vert=False, figsize=(8, 3))
plt.title('Petal length by species')
plt.show()

iris is unusually tidy: exactly 50 flowers per species, no missing values, and already ordered by group.

penguins = sns.load_dataset('penguins')

Complication 1: groups of different sizes¶

The three species contain 152, 124, and 68 penguins.

WWW therefore has as many rows as the largest group, and the shorter columns are padded with NaN at the bottom.

This is expected and harmless. Pandas’ plotting functions ignore missing values, so each plot is drawn only from the observations that exist.

print(mass_by_species.count().to_string())

mass_by_species.plot.box(vert=False, figsize=(8, 3))
plt.title('Body mass by species')
plt.show()
species
Adelie       151
Chinstrap     68
Gentoo       123
Note

The counts above are 151, 68, and 123, not 152, 68, and 124.

Two penguins have no recorded body mass. They occupy a row in WWW but contribute a NaN to it.

Complication 2: more than one grouping variable¶

Nothing prevents ggg from being a list. Pass it to .groupby() and to columns, and the result carries a hierarchical column index.

penguins[b_w] = penguins.groupby(['species', 'sex']).cumcount()

penguins.dropna(subset=['sex']).pivot(
    index=b_w, columns=['species', 'sex'], values=b_m).head(3)
Loading...

If you would rather have flat labels, combine the grouping variables into one column first. .str.cat() does this, and it yields NaN wherever either part is missing.

penguins['group'] = penguins.species.str.cat(penguins.sex, sep=' ')
penguins[b_w] = penguins.groupby('group').cumcount()

penguins.dropna(subset=['group']).pivot(
    index=b_w, columns='group', values=b_m).count()
group Adelie Female 73 Adelie Male 73 Chinstrap Female 34 Chinstrap Male 34 Gentoo Female 58 Gentoo Male 61 dtype: int64

Complication 3: missing values in a grouping variable¶

You will have noticed the .dropna() in the last two examples. It is required, and the reason is worth understanding.

.groupby() ignores rows whose grouping value is missing. Those rows belong to no group, so .cumcount() has no number to give them.

penguins[b_w] = penguins.groupby('sex').cumcount()

penguins.loc[penguins.sex.isna(), ['species', 'sex', b_w]].head()
Loading...

Every such row receives NaN as its within-group ID.

If there is more than one of them, they all share the same index value, and the reshape fails.

try:
    penguins.pivot(index=b_w, columns='sex', values=b_m)
except ValueError as e:
    print('ValueError:', e)
ValueError: Index contains duplicate entries, cannot reshape

The message names duplicate entries in the index, which is accurate but not obvious. The duplicates are the missing values.

The fix is to drop those rows before reshaping.

penguins.dropna(subset=['sex']).pivot(index=b_w, columns='sex', values=b_m).count()
sex Female 165 Male 168 dtype: int64
Caution

Assign www first, then drop, then reshape.

Dropping the rows before calling .cumcount() also works, but it changes the dataframe you are working with. This order leaves DDD intact.

What WWW means, and what it does not¶

The manufactured www is a position, not a measurement. It carries no information about the observation.

This limits how WWW may be used.

Warning

The rows of WWW are not aligned in any meaningful way.

The setosa on row 7 has nothing to do with the virginica on row 7. Each is simply the eighth flower of its species in the order the file happened to list them.

It would be a mistake to subtract one column from another, to correlate them, or to treat a row as an observation.

Compare this with the wide table from the previous notebook, where row 1970 genuinely means the year 1970 in every column. There, reading across a row is meaningful. Here it is not.

A WWW built on a manufactured index is a convenience for plotting, not a tidy dataset. Build it, plot it, and return to DDD for anything else.

Controlling the order¶

.cumcount() numbers rows in the order they appear in DDD. It does not sort anything.

So if the numbering should mean something, sort DDD first.

Sorting by the measurement, for instance, makes each column of WWW ascend.

iris_sorted = iris.sort_values([a_g, a_m])
iris_sorted[a_w] = iris_sorted.groupby(a_g).cumcount()

iris_sorted.pivot(index=a_w, columns=a_g, values=a_m).head()
Loading...

For a box plot or a histogram this makes no difference, since those plots do not care in what order the values arrive.

It matters when you want WWW to be readable, or when you intend to take the first nnn rows of each group.

You can see the result more clearly below.

We take a sample from our dataframe and sort by index.

You can also see what we want: have all the data sit side-by-side.

This requires creating and ID value that restarts with each species.

staircase.sample(20).sort_index().fillna('').style.background_gradient()
Loading...
Important

This does not mean that we are getting rid of a unique identifier for each observation in the dataset.

What we are doing is replacing the original ID column, which was just a row ID, with a uniquie key — species, within.

General Function¶

As before, let’s define a general function that takes a tidy dataframe as its first argument and returns a wide dataframe.

This one takes ggg and mmm only, since www is manufactured rather than supplied.

def tidy2wide_all(tidy, g, m, w='within', method='pivot', sort_by=None):

    D = tidy.copy()

    # Sort first if the numbering should mean something
    if sort_by is not None:
        D = D.sort_values(sort_by)

    # Manufacture the index
    D[w] = D.groupby(g).cumcount()

    # Rows with a missing grouping value got no number, so remove them
    keys = [g] if isinstance(g, str) else list(g)
    D = D.dropna(subset=keys)

    if method == 'pivot':
        wide = D.pivot(index=w, columns=g, values=m)
    elif method == 'unstack':
        wide = D.set_index([w] + keys)[m].unstack(keys)
    else:
        raise ValueError("Invalid method.")

    return wide

Summary¶

Three things to remember about the third option.

  • .cumcount() numbers rows in the order they appear, restarting at each group. Sort DDD first if the order should mean something.

  • Groups of different sizes produce a ragged WWW padded with NaN. This is normal, and plotting functions handle it.

  • WWW is not tidy. Its rows are not observations, and reading across a row is meaningless. It is designed to organize the data for vertical (column-wise) analysis and for visualiztion.
